# Thaw Pre-Push Quality Gates & Pull Request Workflow

Follow this checklist before committing, pushing, or opening a PR in Thaw. Full policy: `CONTRIBUTING.md` and `docs/concepts/testing.md`.

## 1. Branch & Git History Rules
- Never commit directly to `main`. Use a conventional branch prefix: `feat/`, `fix/`, `perf/`, `refactor/`, `chore/`, `docs/`, `style/`, `test/`, `build/`, `ci/`.
- **Never alter git history**: do NOT use `git commit --amend`, `git rebase`, or `git push --force`. Always create new commits.
- **Never create or push `v*` tags manually** — `manual-release.yml` runs `semantic-release`.

## 2. Generated-Artifact & Dependency Checks
Run any applicable generators so CI guard tests stay green:
- Changed `internal/app/` or bound `Service` signatures → `wails generate module`
- Added/moved/removed semantic-map annotated files → `go generate ./internal/architecture/`
- Changed `internal/objectkind/kinds.go` → `go generate ./internal/objectkind/`
- Changed `internal/snowflake/datatypes.go` → `go generate ./internal/snowflake/`
- Changed `go.mod` or `frontend/package.json` → `bash scripts/regen_third_party_notices.sh`

## 3. Run Verification & Quality Gates
Run the checks matching your change (run all for Go + frontend changes):
```bash
# Go unit tests + generated-artifact guards
go test ./...
go test -race ./...

# Frontend type-check & unit tests (includes staticModal.test.ts and objectIcons.test.ts)
cd frontend && npx tsc --noEmit && npm test && cd ..

# Static analysis & security (run when touching Go code)
golangci-lint run ./...
govulncheck ./...
gosec -exclude=G104,G115,G122,G201,G204,G301,G304,G306,G703 \
      -exclude-dir=frontend -exclude-dir=internal/integration ./...
```

## 4. Docs-with-Code Audit
Verify every touched area has up-to-date docs **in the same PR**:
- `README.md` — user-facing overview, requirements, shortcuts
- `FEATURES.md` — feature catalogue + toggleable features section
- `CLAUDE.md`, `GEMINI.md`, and `.agents/` — architecture/patterns/rules/skills
- Affected `internal/<pkg>/README.md`, `frontend/src/<dir>/README.md`, and `docs/concepts/*.md`
- Never hand-edit `docs/backend/` or `docs/frontend/` (generated by `make docs`).

## 5. Conventional Commit & Pull Request
1. Inspect the full diff against `main` (`git status`, `git diff main...HEAD`) and stage only intentional files.
2. Commit with a Conventional Commit message (imperative mood, `< 72` chars; `feat` → minor release, `fix`/`perf` → patch release, `feat!`/`BREAKING CHANGE` → major release, `chore`/`docs`/`refactor`/`test`/`build`/`ci`/`style` → no release).
3. Push and open the PR targeting `Technarion-Oy/thaw:main`:
   ```bash
   git push -u origin <branch-name>
   gh pr create --repo Technarion-Oy/thaw --base main \
     --title "<type>: <short imperative title>" \
     --body "$(cat <<'EOF'
   ## Summary
   - <concise bullet 1>
   - <concise bullet 2>

   ## Test plan
   - [ ] <automated / manual verification step 1>
   - [ ] <automated / manual verification step 2>
   EOF
   )"
   ```
   (Only append a `BREAKING CHANGE:` footer if the change is breaking.)
